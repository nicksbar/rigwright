# IC-756PROII hardware validation

- Date: 2026-09-10
- Model: Icom IC-756PROII
- Firmware: not reported by the radio probe
- Protocol: Icom CI-V
- CI-V address: `0x64`
- Controller address: `0xE0`
- Baud: `19,200`
- Transport: USB serial adapter using the Linux PL2303 driver
- Operating state at validation: `14.242 MHz`, Data mode, receive, PTT off
- Load: dummy load used for transmit validation

## Evidence

Rigwright's model-backed `probe_wizard` was run directly against the physical
radio using the stable USB serial device path. The read-only probe passed:

- Frequency read: `14,242,000 Hz`
- Mode read: `Data`
- PTT read: `false`
- Signal meter read: normalized value `4`
- Core-state read: frequency, mode, and receive/PTT state

The safe exercise passed same-value frequency and mode writes, plus readback
round trips for AF gain, RF gain, squelch, preamp, attenuator, noise blanker,
noise reduction, noise-reduction level, notch, manual notch, and AGC.

The dedicated PTT test passed with the dummy load connected:

1. RF power was set to the profile minimum (`0`).
2. PTT asserted and the radio reported transmit.
3. PTT de-keyed successfully.
4. The previous RF-power setting was restored.

## Profile boundaries confirmed

The IC-756PROII manual documents Split as write commands (`0F 00` and
`0F 01`) but does not document a Split read command. The profile therefore
advertises Split as write-only. The manual does not document the generic RIT
offset (`0x21`) or tuner-status (`0x1C 01`) reads used by newer Icom families;
those operations are intentionally not advertised for this model.

The local diagnostic reports are retained in `/tmp` for the session, while this
sanitized record is the durable release evidence. No serial endpoint, raw CI-V
capture, or private host detail is included here.
